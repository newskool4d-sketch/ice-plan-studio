## 2. 페이지 유형 매트릭스 (확정)

### 2.1 문서 앞부분 시퀀스 (문서별 실측)

| 문서 | 시퀀스 |
|---|---|
| A | 표지 → 목차 → 본문 |
| C | 표지 → 사전검토표 → 목차 → 요약 → 본문 |
| D | 표지 → 사전검토표 → 목차 → 요약 → **속표지** → 본문 |
| E | 표지 → 목차 → 사전검토표 안내 → 요약 → 변경사항표 → 속표지 → 본문 |
| B·F·G | 표지 (→G는 속표지) → 바로 본문 (사전검토표·목차·요약 없음) |

**귀결**: 사전검토표·목차·요약·속표지는 **선택형 페이지**다. 본청 기본계획(C·D·E)은
대부분 포함, 실무·운영계획(B·F·G)은 생략. 문서 유형 설정에서 페이지별 on/off를
제공해야 하며, 순서도 고정이 아니라 조정 가능(D는 검토표 먼저, E는 목차 먼저).

| 유형 | 반복 조판 패턴 | 근거 |

### 2.3 장·절 제목 구현 변형 (2계열 확정)

| 계열 | 구현 | 사용 문서 |
|---|---|---|
| 박스형 | 2~3열 표 `\| Ⅰ \| 제목 \|` — 번호 셀 색 채움 + 제목 셀 | A(컬러박스+흰글자)·E·F |
| 배너형 | 반복 배너 이미지 + 장번호·제목 텍스트 | B·D·G |

절 제목: 3열 박스 `| 1 | | 추진 배경 |`(D), 무기호 굵은 명사구(F), `■`(E), `□`(C·D).

### 2.4 항목기호 계층 (문서별 변형 — 규칙 엔진은 "일관성 검사"로 접근)

| 문서 | 계층 |
|---|---|
| A·E | ■/□ → ❍ → − → ·(가운뎃점) |
| B | ❍ → 1. → 가. → − |
| C | ❍ → ❖ → ￭ → − |
| D | ◈(핵심) / □ → ❍ → − → ∙, 절차 ❶❷❸·①②③ |
| F | (무기호 절) → ❍ → − → ㆍ |
| G | 장별 이원(❍ 단층 / ◎→◦→− / 1.→가.→◦) |

**귀결**: 항목기호는 단일 표준 강제가 아니라 **문서 내 일관성**을 검사하고, 프로필별
기본 계열(본청 □→❍→−→· 권장)을 제공하되 사용자가 계열을 선택할 수 있어야 한다.

### 2.5 공통 발견 사항

- **"끝." 표시가 계획안 문서 7종 중 0종에서 사용됨** — 현 규칙 엔진의 END-001은
  공문 본문용 규칙으로, 계획안 문서 유형에는 적용 제외해야 함 (규칙의 문서유형 스코프 필요)
- 병합 셀(rowspan/colspan)·중첩 표가 본청 문서에서 일상적으로 사용됨 — IR의 표 grid
  보존이 필수 (원 계획 §11.7 재확인)
- 특수문자 실사용 풀: ❍ ■ □ ◈ ◎ ◦ ∙ ㆍ ・ ￭ ❖ ※ ☞ ⇨ ➜ ↔ ❶❷❸ ①②③ 【】 「」 ☏ ☎ ′
- 표는 문서 A 기준 전원 repeatHeader=1, 소형 표·박스는 treatAsChar=1이 다수
  (대형 표만 해제) — "표는 무조건 글자처럼 취급 해제"는 오류였음, 크기·역할 기반 분기 필요

   │   부제 18pt(파랑 #0000FF) + 본제목 27pt bold — A는 HY울릉도M
   └ r2 하단 스트라이프(2mm): 43mm+43mm+86mm (A: #3057B9 + #FF0000×2)

## 5. kordoc 통합 스파이크 결과

- **kordoc = npm 패키지, 로컬 실설치 버전 4.1.0**(`~/mcp-servers/kordoc/node_modules/
  kordoc/package.json` 확인. 최초 기록한 "4.2.3"은 `npm view`로 조회한 **레지스트리
  최신판**을 착각 기재한 것 — 정정). HWP3-5·HWPX·PDF·DOCX 파싱, lossless patch/
  roundtrip, SVG/PNG 렌더러 포함. → Electron main에 라이브러리로 직접 통합하는
  경로는 유효하나, **앱 `package.json`에는 아직 의존성으로 추가되지 않았다** —
  MCP 도구로 가능성만 스파이크했을 뿐 실통합은 REBASELINE_PLAN §8 재작업 항목
- HWP 구조 파싱 실증: 레퍼런스 B·D·E·F·G 5종 모두 제목 계층·병합 표·이미지 보존 파싱 성공
- 렌더 실증(주의): 우리가 생성한 HWPX(표지 포함 9쪽)를 `render_document`로 PNG 렌더
  성공. 단 이 도구 자체가 "AI 생성본은 캐시가 없어 순수 조판 엔진(reflow)으로 렌더되며
  한컴 실조판의 **근사치**"라고 명시한다 — 한컴 출력과의 위치·줄바꿈·페이지 경계 일치를
  증명하지 않는다. **한컴 출력과의 실제 일치 근거는 §6의 한글 2020 COM 실물 열람·PDF
  변환뿐**이며, 이 kordoc 렌더는 "한컴 미설치 환경에서 쓸 수 있는 참고용 대체 미리보기"
  후보로만 기록한다.
