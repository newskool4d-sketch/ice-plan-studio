## 1. 개선 목표

학교에 배포되는 기본계획을 다음 순서와 조판 원칙으로 안정적으로 생성한다.

1. 표지
2. 목차
3. 요약(선택 또는 원문 보존)
4. 본문 시작 쪽
5. 본문 후속 쪽
6. 세부 과제·일정·붙임

이번 개선의 핵심은 글자 크기 몇 개를 일괄 변경하는 데 있지 않다. 현재 하나의 `body`로 처리하는 본문을 **본문 시작 쪽**과 **본문 후속 쪽**으로 구분하고, 목차·요약의 존재 여부와 생성 범위를 사용자 결정으로 명시하는 데 있다.

## 3. 자료 분석 결과

### 3.1 기준 PDF의 쪽 구성

| 쪽 | 역할 | 확인된 특징 |
|---:|---|---|
| 1 | 표지 | 독립 표지 |
| 2 | 목차 | 제목 틀, 색상선, 항목·점선·쪽 번호, 붙임 항목 포함 |
| 3 | 요약 | 제목, 정의, 비전, 목표, 3개 추진과제, 추진단계, 협력체계 |
| 4 | 본문 시작 | 다색 상단선, 회색 제목 띠, 슬로건, 문서명, 담당 부서, 첫 장 제목 |
| 5 이후 | 본문 후속 | 문서 전체 제목 띠를 반복하지 않고 장·절 제목과 내용만 계속 배치 |

따라서 `본문 상단 제목 틀`은 모든 본문 쪽에 반복되는 일반 머리말이 아니라 **첫 실제 내용 쪽 전용 구성**으로 본다.

### 3.2 실측 글자 크기

아래 값은 기준 PDF에서 추출한 크기이며 모든 문서에 일괄 강제할 전역값이 아니라 해당 레이아웃 프로필의 기준값이다.

| 요소 | 기준 크기 | 비고 |
|---|---:|---|
| 본문 | 14pt | HCRBatang 계열 |
| 장 제목 | 18pt | 로마숫자 상자와 함께 사용 |
| 본문 시작 쪽 문서명 | 24pt | 상단 제목 틀의 주 제목 |
| 본문 시작 쪽 슬로건 | 16pt | 문서명 위 |
| 인용·근거 설명 상자 | 11pt | 색상 배경 상자 안 |
| 쪽 번호 | 10pt | 앞부분을 제외하고 본문부터 시작 |
| 목차 제목 | 20pt | `목 차` |
| 목차 주요 항목 | 17pt | 장 항목 |
| 목차 붙임 항목 | 15pt | 하위 또는 붙임 |
| 요약 쪽 주 제목 | 22pt | 요약 표제 |
| 요약 쪽 상자 본문 | 11~14pt | 상자 역할에 따라 차등 |

현행 `layout-tokens.json`의 본문 12pt·장 제목 14pt는 이 기준 PDF 프로필과 일치하지 않는다. 또한 `documentModel.js`는 맑은 고딕 11pt, 빠른 미리보기는 10.5px를 사용하므로 현재는 정본이 세 갈래로 나뉘어 있다.

### 3.3 기본계획 유형별 상단 구성

캡처 3과 캡처 4는 하나의 고정 머리말이 모든 기본계획에 통용되지 않음을 보여준다.

| 프로필 후보 | 본문 시작 쪽 | 본문 후속 쪽 |
|---|---|---|
| 세계시민교육형 | 다색선 + 회색 제목 띠 + 슬로건 + 문서명 + 담당 부서 | 제목 띠 생략, 장·절 구조만 유지 |
| 학생맞춤지원형 | 상단 문서명 선틀 + 회색 그라데이션 대단원 띠 | 문서명 선틀 생략, 번호 상자와 절 제목만 유지 |

따라서 하나의 헤더를 전역 적용하지 않고 `layoutProfile`에 따라 시작 쪽 상단 구성을 선택한다.

## 4. 현행 구현과의 핵심 격차

| 영역 | 현행 | 개선 필요 |
|---|---|---|
| 스타일 정본 | 문서 모델 11pt, 토큰 12pt, 빠른 미리보기 10.5px, Python 하드코딩이 병존 | 레이아웃 프로필을 단일 정본으로 만들고 미리보기·HWPX가 함께 소비 |
| 쪽 유형 | `body` 한 종류 | `body-opening`과 `body-continuation` 분리 |
| 기본 쪽 순서 | 쪽 정보가 없으면 `cover + body` | 기본계획은 목차 정책 결정 전 다음 단계로 진행하지 않음 |
| 목차 감지 | 입력의 목차를 전용 쪽으로 분리하지 않음 | 원문 목차 감지·보존·전용 렌더 |
| 목차 미존재 | 질문·결정 상태 없음 | 사용자에게 포함 여부를 묻고, 선택 시 **빈 틀만** 생성 |
| 요약 | `요약 내용 입력` 한 문단 | 원문 요약 보존 또는 빈 요약 틀 선택. 자동 요약 금지 |
| 쪽 추가 | 기존 쪽 유형 변경만 가능 | 목차·요약 쪽의 삽입·제거·순서 변경 지원 |
| 본문 시작 제목 틀 | HWPX에는 없음 | 프로필별 전용 생성기 구현 |
| 불릿 | 규칙 제안과 무시는 가능 | 원문 기호 보존, 시각 들여쓰기, 명시적 사용자 override 기록 |
| 검은 마킹 | 구현 근거 없음 | 모든 산출물에서 부재를 단정하는 제외 조건 추가 |
| 적응 조판 | 12pt 함초롬바탕 기준으로 교정 | 14pt 프로필별 재교정 전 기존 임계값 재사용 금지 |

## 5. 기능 요구사항

### R-01. 문서 유형 확인

- 입력 분석 후 `학교 배포용 기본계획`, `내부 계획`, `기타` 중 용도를 확인한다.
- `학교 배포용 기본계획`이면 목차 결정이 완료되기 전 내보내기를 허용하지 않는다.

### R-02. 목차가 있는 입력

- 입력에서 목차 제목·항목·쪽 번호·붙임 항목을 감지한다.
- 감지한 원문을 전용 목차 쪽에 보존해 렌더한다.
- 원문에 없는 항목이나 쪽 번호를 임의로 합성하지 않는다.
- 본문 재조판으로 쪽 번호가 변하는 경우에는 사용자 승인 후 쪽 번호만 재계산할 수 있다.

### R-03. 목차가 없는 입력

- 다음 질문을 표시한다: `목차 쪽이 없습니다. 목차 틀을 추가할까요?`
- 학교 배포용 기본계획의 권장 기본값은 `빈 목차 틀 추가`로 한다.
- 사용자가 추가를 선택하면 제목·장식·항목 배치 영역만 만들고, `목차 항목 입력` 같은 합성 본문은 넣지 않는다.
- 사용자가 제외를 선택하면 결정과 경고 확인을 프로젝트 기록에 남긴다.

### R-04. 요약 쪽

- 원문 요약이 있으면 요약 내용을 보존하고 전용 쪽으로 렌더한다.
- 원문 요약이 없으면 `빈 요약 틀 추가` 또는 `추가하지 않음`을 선택하게 한다.
- 빈 틀은 제목·비전·목표·추진과제·추진단계 등 입력 영역만 제공한다.
- 전체 본문을 바탕으로 한 자동 요약 또는 AI 요약은 이번 범위에서 생성하지 않는다.
- `요약 내용 입력` 같은 합성 문장을 최종 HWPX/PDF에 넣지 않는다.

### R-05. 본문 시작 쪽

- 표지·목차·요약 다음의 첫 실제 내용 쪽을 `body-opening`으로 지정한다.
- 프로필에 따라 상단선·제목 띠·슬로건·문서명·담당 부서를 배치한다.
- 장 제목은 번호 상자, 제목, 하단선 또는 프로필 지정 장식으로 구성한다.
- 앞부분과 분리해 이 쪽부터 문서 쪽 번호를 시작할 수 있어야 한다.

### R-06. 본문 후속 쪽

- `body-continuation`에는 전체 문서명 제목 띠를 반복하지 않는다.
- 장·절 번호, 본문, 표, 목록의 연속성만 유지한다.
- 쪽이 나뉘어도 제목 띠가 잘못 재삽입되지 않도록 한다.

### R-07. 불릿·항목기호

- 원문의 불릿·항목기호와 들여쓰기 수준을 우선 보존한다.
- 공문서 기재 요령과 레퍼런스 관행은 **권고**로 제시하고 자동 강제하지 않는다.
- 담당자 재량으로 다른 기호를 선택하거나 권고를 무시할 수 있어야 한다.
- 선택 결과와 원문 기호를 모두 보존하여 저장·다시 열기·HWPX 왕복 후에도 동일하게 복원한다.
- 목록 수준은 데이터뿐 아니라 실제 미리보기와 HWPX 들여쓰기에 반영한다.

### R-08. 검은 표시 제외

- 캡처의 검은색 가로 표시는 줄간격 설명용이며 산출물 요소가 아니다.
- 해당 표시를 토큰, 장식, 선, 이미지 또는 문단 배경으로 구현하지 않는다.

### R-09. 글자 크기와 적응 조판

- 기준 PDF의 14pt 본문은 `세계시민교육형` 프로필에 우선 적용한다.
- 다른 기본계획에 전역 강제하지 않고 프로필별 기준값으로 둔다.
- 본문 기준 크기를 줄여 한 쪽에 억지로 맞추지 않는다.
- 14pt 프로필에 대해 줄간격 사다리·채움률 임계·표 넘침을 다시 교정한 후 적응 조판을 활성화한다.

## 6. 목표 페이지 모델

```text
cover
  └─ toc(source | template)
       └─ summary(source | template | omitted)
            └─ body-opening
                 └─ body-continuation*
                      └─ task | schedule | appendix
```

권장 중간 모델은 다음 결정을 명시적으로 가진다.

```json
{
  "documentKind": "school-guidance-basic-plan",
  "layoutProfile": "worldschool-2026",
  "toc": {
    "mode": "source",
    "contentGeneration": "none",
    "userDecision": "confirmed"
  },
  "summary": {
    "mode": "template",
    "contentGeneration": "none",
    "userDecision": "confirmed"
  },
  "bodyOpeningHeader": {
    "profile": "worldschool",
    "repeatOnContinuation": false
  },
  "bulletPolicy": {
    "mode": "preserve-with-suggestions",
    "overrides": []
  }
}
```

`toc.mode`와 `summary.mode`의 허용값은 `source`, `template`, `omitted`로 고정한다. `template`은 빈 틀을 뜻하며 합성 문장을 뜻하지 않는다.

| 영역 | 주요 파일 | 변경 방향 |
|---|---|---|

## 8. 단계별 실행 계획

## 10. 검증 명령과 판정 원칙

구현 단계에서 다음 명령을 기본 회귀 묶음으로 사용한다.

```powershell
npm run build
npm run verify:plan-ir
npm run verify:preview-equivalence
npm run verify:rules
npm run verify:workspace-packages
npm run verify:app-render
npm run verify:workflow-walk
npm run calibrate:layout-measure
npm run verify:adaptive-layout
```

판정은 서로 분리한다.

| 게이트 | 의미 |
|---|---|
| 구조 검증 | IR·XML·ZIP·텍스트 보존 |
| 미리보기 검증 | React 미리보기와 HWPX projection 동등성 |
| 규칙 검증 | 불릿 권고·무시·override 왕복 |
| CDP 검증 | 패키징된 앱의 실제 렌더·클릭 흐름 |
| 한글 COM 검증 | 실제 열기·쪽수·PDF 변환 |
| 사용자 검토 | 기준 자료와의 시각 차이 최종 확인 |

한 게이트의 통과로 다른 게이트까지 통과했다고 간주하지 않는다. 실행하지 못했거나 증거가 없으면 `PARTIAL`, 명시적 오류는 `FAIL`, 모든 독립 게이트와 사용자 확인을 마친 경우에만 최종 `PASS`로 판정한다.

## 11. 현재 검증 환경 제약

- 이전 재개 지점에서 한글 COM은 `HWPFrame.HwpObject` Dispatch 단계가 차단된 상태로 보고되었다.
- 설치 앱 CDP 검증도 렌더러 target 종료 문제가 있어 최종 실주행 증거가 미완성이다.
- 따라서 정적 구조·스크립트 게이트를 먼저 진행할 수는 있으나, 이 두 외부 실물 게이트를 통과하기 전에는 완료로 판정하지 않는다.
- 구현 착수 전 위 상태를 다시 실측하여 오래된 장애인지 현재도 재현되는 장애인지 구분한다.

## 12. 범위 제외

- 캡처의 검은색 마킹 구현
- 본문을 읽어 요약문을 자동 작성하는 기능
- 원문에 없는 목차 항목·쪽 번호·정책 내용을 임의 생성
- 모든 문서의 본문을 전역 14pt로 강제
- 공문서 기재 요령을 이유로 사용자의 불릿 선택을 강제 교체
- 기준 PDF의 업무 본문이나 개인정보를 테스트 fixture에 복제

## 13. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 14pt 전역 적용으로 다른 문서가 무너짐 | 문서별 `layoutProfile`로 격리 |
| 시작 쪽 제목 틀이 후속 쪽에 반복됨 | 쪽 역할을 IR에서 분리하고 개수 단정 |
| 빈 틀에 안내 문구가 최종 출력됨 | 합성 본문 0건 게이트 |
| 목차 쪽 번호가 재조판 후 틀림 | 사용자 승인 기반 재계산 단계 분리 |
| 미리보기와 HWPX가 다시 갈라짐 | 동일 토큰 소비 + projection 동등성 게이트 |
| 불릿 권고가 강제 교정으로 변질됨 | 원문·권고·사용자 결정 3개 필드 분리 |
| 기존 12pt 적응 조판 교정값 오용 | 14pt 전용 교정 완료 전 기능 비활성 |
| 현재 작업트리의 다른 수정과 충돌 | 단계별 파일 소유권 확인, 별도 커밋 범위 유지 |

## 14. 착수 전 승인할 기본 결정

다음 값을 권장 기본안으로 둔다.

1. 14pt 본문은 우선 `worldschool-2026` 프로필에만 적용한다.
2. 본문 시작 쪽 상단 틀은 최소 `세계시민교육형`, `학생맞춤지원형` 2종을 지원한다.
3. 학교 배포용 기본계획에 목차가 없으면 `빈 목차 틀 추가`를 기본 선택값으로 제시한다.
4. 요약이 없으면 `빈 요약 틀 추가`와 `추가하지 않음`을 사용자가 선택한다.
5. 자동 목차 내용 작성과 자동 요약 작성은 하지 않는다.
6. 불릿 규칙은 권고로 유지하고 담당자의 선택을 보존한다.

이 결정이 승인되면 단계 0~1부터 구현을 시작한다. 구현 중 요구사항을 변경해야 할 경우에는 근거, 영향 fixture, 회귀 범위를 먼저 갱신하고 다시 승인받는다.
