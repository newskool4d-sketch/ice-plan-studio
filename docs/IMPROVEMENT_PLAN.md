## 2. 개선 과제

### 과제 A — 기관 레지스트리 (25+ 기관 실명 반영)

- `agencyProfiles.js`를 **기관 레지스트리**(`agencyRegistry.js`)로 재설계: 유형(본청 / 교육지원청 / 직속기관 / 도서관) × 기관 배열 구조
- 교육지원청 7종: 남부·북부·동부·서부·강화·영종·검단 (`인천광역시○○교육지원청` 형식)
  - **영종·검단은 2027. 3. 1. 개청 예정** → `activeFrom` 필드로 조건부 노출(개청 전에는 "예정" 배지와 함께 선택 가능하되 경고)
- 직속기관 10종: AI융합교육원 / 교육연수원 / 학생교육문화회관 / 학생교육원 / 교직원수련원 / 평생학습관 / 유아교육진흥원 / 동아시아국제교육원 / 학교지원단 / 난정평화교육원 (+ 영문명 필드)
- 도서관 8종: 신트리·중앙·부평·주안·화도진·서구·계양·연수
- **기관 공식 명칭 전수 확인**(3자 검토 반영): 착수 시 공식 직제 대조 필수 — 특히
  "인천광역시동아시아국제교육원"은 제공 목록상 유일하게 '교육청'이 없는 명칭이며,
  학교지원단의 직제상 지위(직속기관 여부)도 확인. 개청 전 기관은 "(가칭)" 라벨 폴백
- UI: 현행 드롭다운 → **유형 그룹 + 검색 가능한 기관 선택기**
- 표지 프로필 매핑: 기관 유형별 기본 coverProfile 지정(본청 A / 교육지원청 A변형 / 직속기관 B·F·G / 도서관 미정 — 레퍼런스 확보 후 결정), 기관 단위 override 허용

### 과제 B — 공문서 항목기호 체계

- **불릿 팔레트**: corpus 실측 마커(■ □ ❍ ◈ ❖ ◎ ◦ ￭ − · ∙ ㆍ) + 공문 상용 기호를 팔레트로 정의, 구조편집 단계에서 목록별 선택 가능
- **위계 검증 규칙**(규칙 엔진 확장): `Ⅰ.` → `1.` → `가.` → `1)` → `가)` → `(1)` → `(가)` → `□·○`
  - 위계 건너뜀(Ⅰ. 다음에 바로 가.), 동급 혼용(1.과 ①이 같은 레벨), 미승인 기호를 검출·교정 제안
  - **전거 명확화**(3자 검토 반영): 행정업무운영 편람의 공문 항목기호 체계에는 로마숫자가
    없음 — 위 위계는 편람 그대로가 아니라 **계획안(비서식 문서) 관행 + 레퍼런스 실측**이
    기준임. 착수 시 편람 최신판(korean-law-mcp)과 corpus 실측을 병기해 검증 기준을 확정
  - **선행 수정**(3자 검토 반영): `plan-ir.cjs` 목록 레벨 계산이
    `Math.floor(line.search(/\S/)) / 2`로 floor가 나눗셈 밖 — 홀수 들여쓰기에서 0.5 같은
    소수 레벨 발생. 위계 검증은 레벨 정확성이 전제이므로 파서 레벨 정규화를 8단계 첫
    작업으로 수행
- **관용 장 구조 인식**(사용자 실무 지침, 2026-07-21): 계획안 앞머리(`Ⅰ.`~`Ⅲ.`)에 통상 근거·목적·방침 장이 오지만 **매번 그렇지는 않음** — 위치가 아니라 **장 제목 내용으로 판정**한다
  - 장 제목이 **근거 / 목적 / 방침 / 배경** 계열(추진 근거, 추진 배경 등 변형 포함)인 경우에만 하위 세부 내용의 기본 기호를 불릿 `○`로 제안
  - 판정은 제목 텍스트 매칭 기반(위치 무관) — 해당 계열이 아니면 일반 위계 규칙 적용
  - **키워드 목록 확정 절차**(3자 검토 반영): "계열 변형 포함"은 그대로는 구현 불가 —
    착수 시 확정 키워드 목록(필요성·개요 등 포함 여부)을 사용자와 확정해 fixture로 고정
  - 규칙 엔진: 해당 장 하위에 다른 위계 기호(1. 가. 등)가 깊게 전개되면 "관용상 ○ 불릿 권장" 제안(강제 아닌 suggestion — 문서마다 예외 존재)
  - MD/TXT 입력 시 해당 장의 무기호 목록은 `○`로 기본 매핑
- 문서 프로필별 기호 계열 저장(기관마다 선호 계열이 다름 — corpus의 `rules.itemMarkers`를 실제 소비)

### 과제 C — 분량 적응 문단 간격

- **2-pass 구조로 설계**(3자 검토 반영 — 1-pass 추정만으로는 구현 불가 판정):
  현행 `estimate_wrapped_lines`는 문자폭 900 고정 근사라 채움률 105~115% 경계 판정에
  필요한 정밀도가 없음. **1차 생성 → 높이 측정 → 간격 재조정 → 재생성** 루프로 설계하고,
  측정기는 COM(비결정성 리스크)이 아니라 **kordoc reflow 렌더 높이**를 사용(오프라인
  동작·결정적). COM은 최종 게이트 검증에만 사용
- 채움률 구간별 보정: 예) 1쪽 105~115% 초과 시 줄간격 160→150%·문단 아래 간격 축소로 1쪽 수렴 시도, 85% 미만 시 간격 완화(공문 관행: 한 쪽을 적절히 채움)
- 보정 결과는 미리보기·검수 단계에 "간격 자동 조정됨" 고지(묵시 변경 금지)
- 게이트: 경계 분량 fixture(딱 넘침/딱 모자람)로 COM 실측 쪽수 검증 + kordoc 측정치와
  COM 실측치의 오차율 기록(측정기 신뢰도 검증)

**구현 결과(2026-07-23, 9단계 완료)** — 상세는 `apps/desktop-prototype/test-data/adaptive-layout/README.md`
- 측정기 교정에서 **가정이 깨진 지점 2건**을 잡았고, 이것이 이 단계의 실질 산출이다:
  ① kordoc reflow는 줄높이를 한글보다 **4~6% 작게** 잡는다 ② **표 넘침을 쪽으로 나누지
  않는다**(채움률만 1.0을 넘김). 둘 다 그대로 두면 "조이기 성공" 판정이 한글에서 거짓이 된다.
  → 채움률 안전 임계 `0.945`(COM 실측 경계 0.931↔0.962의 중앙)를 넘으면 쪽수를 +1 보정.
  본문 12pt 함초롬바탕 기준이므로 **본문 글꼴·크기 변경 시 재교정 대상**
- 간격 사다리는 **줄간격만** 쓴다 — 레퍼런스 paraPr 73의 문단 아래 간격(`hc:next`)이 이미
  0이라 줄일 여지가 없음(계획 수립 시 가정과 다름). 조이기 160→140%, 완화 160→180%
- 조정 주입은 `model_to_hwpx.py --line-spacing/--para-next` → 패치된 header.xml을
  `build_hwpx.py --header`로 전달. **후처리 변조가 아니라 매 pass 재생성(멱등)**
- 미리보기·내보내기가 같은 보정 경로(`generateFitted`)를 공유 — 한쪽만 보정하면 화면과
  출력이 갈라진다. 조정 시 미리보기 배너 + 내보내기 알림으로 고지(묵시 변경 금지)
- 알려진 비용: 보정 루프가 후보 HWPX를 여러 번 생성(조이기 최대 4회·완화 최대 2회 추가)

### 과제 D — 글자 단위 줄바꿈

- 생성 paraPr에 `breakSetting`(breakNonLatinWord = 글자 단위) 명시 — 한글 기본 동작 의존 제거
- 원칙: **본문·표 셀은 글자 단위**, 단 날짜(`2026. 7. 21.`)·법령명(「···」)·금액 등 **분리 금지 토큰은 넘버링 보호**(줄 끝에서 통째로 넘김 — 한글의 "외톨이줄 보호"와 별개로 non-breaking 처리 검토)
- **게이트 영향 사전 조정**(3자 검토 반영): non-breaking 처리는 NBSP 등 특수문자 삽입
  = 텍스트 변조이므로 1단계 semantic projection 동등성 게이트와 충돌 —
  `normalizeText`가 NBSP를 일반 공백으로 정규화하도록 게이트를 먼저 조정 후 구현
- 실측 검증: 레퍼런스 HWP의 breakSetting 값을 먼저 추출·대조 후 동일 값 채택(추정 금지).
  레퍼런스가 이미 글자 단위라면 격차 진단 자체가 무효일 수 있음(한글 기본 동작 확인 선행).
  breakSetting 변경은 템플릿 header.xml paraPr 수정(전 문단 영향)이므로 신규 paraPr 추가
  방식과 비교 후 결정

### 과제 E — 표지 앵커 정밀 고정 + 기관 브랜딩 주입

- **후속 착수 조건**: ① 한글의 PAPER 원점 오프셋 9.0mm를 실측 교정 ② 앵커 문단 처리로 쪽수
  회귀 제거. 둘 다 풀린 뒤에만 전환한다 — 반쯤 교정된 절대 배치는 현행보다 나쁘다
- 대안 검토거리: 제목틀 표를 고정 높이로 만들어 CI를 밀지 않게 하는 방법(긴 제목 잘림 위험 확인 필요)
- **절대 배치 폴백**(3자 검토 반영): kordoc reflow는 하드 쪽 나눔도 못 읽는 것이 실측됨
  (2026-07-21, preview-split로 우회 중) — `vertRelTo="PAPER"` 절대 배치는 미지원 가능성이
  높음. 스파이크 실패 시 **표지 페이지만 React 빠른 미리보기로 대체**하고 실조판 SVG는
  2쪽부터 표시하는 폴백을 기본 설계에 포함(10단계가 kordoc 한계에 블로킹되지 않도록)
- **기관 자체 슬로건·CI 반영 — 하이브리드 권장** (§4 열린 결정 1):
  - 프로그램에 기관별 기본 자산 내장(레지스트리와 함께 배포, 25개 기관 CI 수집 필요)
  - `.iceprofile`의 `branding.customByAgency`로 교체 가능(이미 스키마 존재 — 표지 생성 파이프라인에 연결하는 작업이 본체)
  - 자산 없는 기관은 본청 CI 폴백 + 검수 단계 경고
  - **배포 범위 내부 한정 명시**(3자 검토 반영): 타 기관 CI를 설치본에 내장·배포하는 것은
    내부 업무용 한정으로 명시 — 설치파일 외부 반출 시 기관 사용 허가 확인 필요
  - CI 치수 편차 대응: 앵커 `curSz`와 다른 비율의 CI는 종횡비 유지 축소 배치(비율 보정 로직)
- 슬로건 이미지도 동일 구조(배너 슬롯 교체형)

### 과제 F — UI/UX 전면 리디자인

- 방향: "행정 도구"가 아니라 **"조판 스튜디오"** — 문서가 주인공인 캔버스 중심 레이아웃
- 작업 항목:
  - 디자인 시스템 정립: 인천교육 브랜드 색(현 DESIGN.md 초안) 기반 토큰화(색·타이포·간격·그림자), 다크모드 대응
  - 6단계 워크플로 시각 재구성: 진행률 시각화, 단계 게이트 상태(잠김/진행/완료) 애니메이션, 단계 간 전환 트랜지션
  - 미리보기 강화: 빠른 미리보기 ↔ 실조판 SVG 나란히 비교 모드, 쪽 썸네일 스트립, 규칙 위반 위치 오버레이 하이라이트
  - 기관 선택기: CI 미리보기 포함 카드형 선택 UI
  - 마이크로 인터랙션: 내보내기 진행 상태, 성공 시 파일 위치 바로가기, 드래그&드롭 입력
  - 접근성: 키보드 내비게이션, 명도 대비 WCAG AA
- **선행 리팩터링**(3자 검토 반영): 현행 `WorkflowApp.jsx`는 565줄 단일 파일 —
  리디자인 착수 전 단계별 컴포넌트 분리(기능 무변경 리팩터링 + 전 게이트 재통과)를
  11단계 첫 작업으로 수행해 시각 변경과 로직 변경을 분리
- 방법: `insane-design` 스킬로 디자인 시스템 추출·적용 → 정적 시안 승인 → 구현 (시안 승인 게이트 필수)

### 과제 G — 기반 정비 (발전적 개선을 받치는 것)

- 회귀 하네스에 kordoc pageCount 대조 추가(이번에 잡은 결함 클래스 자동화 — `verify-app-render.mjs` 활용)
- 앱 버전 0.1.0 → 단계별 상향 + 설치본 자동 빌드 검증(`verify-app-render.mjs`를 빌드 후 필수 게이트로)
- 레퍼런스 corpus에 교육지원청·도서관 실물 문서 추가 수집(현행 A~G는 본청·직속기관 편중)

## 4. 열린 결정 (착수 전 확인 필요)

1. **슬로건·CI 입력 방식** — 권장: **하이브리드**(프로그램 내장 기본 + `.iceprofile` 교체). 근거: ① 25개 기관 자산을 내장하면 일반 사용자는 선택만으로 끝 ② 기관 담당자가 자산을 갱신할 통로(.iceprofile)가 이미 스키마에 존재 ③ 순수 입력 방식은 매 문서 반복 작업, 순수 내장은 자산 갱신마다 재배포 필요. **단, 25개 기관 CI·슬로건 원본 이미지 수집이 선행 과제** — 사용자 제공 필요(홈페이지 저해상도 로고는 인쇄 품질 미달 우려).
2. 도서관 표지 프로필 — 레퍼런스 문서 미확보. 실물 계획안 1건 제공 시 프로필 확정 가능.
   **교육지원청 레퍼런스도 동일**(3자 검토 반영) — "A변형" 프로필은 교육지원청 실물
   계획안 없이는 구현 불가. 미확보 시 7단계에서는 기관명만 반영하고 coverProfile은
   본청 A 재사용(임시).
3. 슬로건 문구/이미지 갱신 — 사용자가 "이후 별도 업데이트"로 명시(memory 기록됨). 7단계에서는 구조(슬롯)만 만들고 자산은 폴백.
4. 항목기호 8단계의 전거 — 행정업무운영 편람 최신판 확인 후 확정(유권해석 필요 시 명시).
