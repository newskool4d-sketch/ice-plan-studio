## 0. 결론

- **디자인보다 무결성이 먼저**: 앱 흐름을 거친 표가 머리글 중복·자동수정 행 밀림으로 **내용이 훼손됨**(재현 확인, 사용자 수정본에도 잔존) → 13단계 긴급 분리
- 공문서 구현의 핵심 공백은 규칙 검수가 아니라 **파서·조판 단계**: 항목 체계(`1)`·`가)`·`①`·`㉮`) 소실, 위계 들여쓰기 역전, Markdown 문법 누출
- 디자인은 표지가 이미 실물급 — 격차는 **목차·요약·본문 위계·표·붙임** 5영역. 기록된 사용자 판정과 충돌하는 항목은 §6 판정 후 착수

### 13단계 상세 — 무결성 긴급

1. **선행 확인**: 설치본 v0.12.11을 CDP로 실주행해 표 포함 MD 내보내기 → 머리글 중복 실재 확인(이번 재현은 앱 동등 흐름)
2. **근본 수정**: 미리보기 전용 투영 필드(`rows`에 머리글 포함, `columnWidthsHwpUnit`·`rowHeightsHwpUnit`)가 저장 모델(`metadata.pages`)로 새지 않게 차단 — 표는 `table.cells`를 단일 원천으로, `header`·`rows`는 파생값으로만 사용. `writeTarget` 인덱스 보정만으로 막지 않음(증상 은폐, 머리글 중복 잔존)
3. **저장본 복구**: `.iceplan` 불러오기 시 `table.cells`가 있으면 `header`·`rows`를 cells에서 재구성 — '전체 적용'으로 `header`·`rows`만 훼손되고 cells는 정상(재현 확인). 둘이 다른 칸은 경고 배너에 목록 표시. cells가 없을 때만 머리글 중복 행 제거로 폴백. `approval.edits` 기록 중 TIME-FORMAT 오탐(`N시간`→`HH:MM간`, 범위 절반 변환)은 되돌리기 제안. 릴리스 노트에 "기존 HWPX 산출물 표 점검" 안내 명기(묵시 결함 금지 규칙)
4. **TIME-FORMAT 교정**: 기간·일반어 제외(`N시간`, 숫자 뒤 `시기·시설·시작·시점` 등 — 목록은 fixture로 확정), 범위는 통째 변환(`14~17시`→`14:00~17:00`), '전체 적용' 대상에서 제외(개별 승인만)
5. **전 구간 대조 게이트** `verify:e2e-fidelity` 신설: MD·HWPX 입력 → `pageDraftsFrom`·`withPagePlan` → `applyAllRuleSuggestions` → HWPX → 표·목록 텍스트 추출 → 입력과 일치 단정 + 변형 테스트(I-1·I-2 재주입 시 실패). 씨앗: 이번 재현 스크립트
6. **COM 복구**: 한글 COM `Open` 멈춤(2026-08-06~, 보안모듈 등록 의심) 해소 시도. 미해결 시 13~17단계 게이트의 '실물 확인'은 **사용자 한글 열람 확인**으로 대체 명시

- 게이트: ① 폭염 계획 MD를 앱 흐름으로 내보낸 HWPX의 데이터 표 10개에서 머리글 행 각 1회, 전 셀 텍스트 입력과 일치 ② '전체 적용' 후 머리글·행 순서 불변 ③ 기간·일반어 fixture 오탐 0건, `14~17시`→`14:00~17:00` ④ 변형 테스트 실패 확인 ⑤ 훼손된 `.iceplan`(재현본)을 불러오면 표가 MD 원문과 일치하게 재구성(오탐 되돌리기 승인 후) ⑥ 기존 게이트 무회귀 + CDP 실주행 내보내기 1회

- 파서: 항목기호 8단계(`1.` `가.` `1)` `가)` `(1)` `(가)` `①` `㉮`) + 특수기호(`□ ○ ❍ - ㆍ` 등)를 목록으로 인식, 들여쓰기는 전각 공백·반각 공백·탭을 폭으로 환산해 레벨 산정. 줄 병합은 기호 없는 이어짐 줄에만 적용
