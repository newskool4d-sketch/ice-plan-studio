## 1. 진단 요약

현재 구현은 "범용 HWPX 생성 기술검증본"이다. 원 계획서가 확정한 제품(교육청 계획안
자동서식 도구)과의 격차는 기능 누락이 아니라 **아키텍처 계층 자체의 부재**다.

| 계층 | 원 계획 | 현재 | 판정 |
|---|---|---|---|
| 입력 어댑터 | HWP·HWPX·MD·TXT → 공통 IR | MD/TXT만. HWP 차단, HWPX는 텍스트 추출 후 구조 소멸 (`App.jsx handleFileLoad` 확인) | **재설계** |
| 문서 IR | 원문 추적·의미 역할·승인 상태 포함 | `{type, text, rows}` 수준 flat 배열 | **교체** |
| 페이지 유형 엔진 | 표지~부록 유형별 조판 | 없음 — 모든 문단을 동일 규칙으로 나열 | **신규** |
| 스타일 토큰 | 레퍼런스 실측 기반 | 범용 gonmun 템플릿 ID 차용 (선언은 맑은고딕, 실출력 함초롬바탕) | **교체** |
| 미리보기 | 출력과 동일 모델 | 정적 데모(164→160mm)와 실데이터 혼재, 조판 결과 미반영 | **교체** |
| 규칙 엔진 | 공문서 규칙 전반 | 5개 검사만 | **확장** |
| 검증 체계 | 구조+실물 분리 | COM 실물검증·CDP 확립됨 | **재사용** |

수치 불일치 사례(모두 이번 재검증에서 확인): 표 폭 — 생성기 150mm(42520HWPUNIT),
UI 표기 160mm, **실제 본청 레퍼런스 170mm**. 셋 다 다르다.

## 2. 사용자 확정 결정 (본 계획의 전제)

1. CI·슬로건은 **원칙적으로 표지에만** 사용한다.
2. 본문 페이지 반복 노출은 예외(옵션)로 다룬다.
3. 페이지들은 동일하지 않지만 **반복되는 조판 패턴**이 있고, 이 패턴 추출이 제품의 핵심이다.
4. 페이지 유형을 구분한다: 표지 / 사전검토표 / 목차 / 요약 / 일반 본문 / 세부과제 /
   일정·예산·성과표 / 부록 (0단계 실측에서 **속표지**가 추가 발견되어 9종으로 확정
   — §BASELINE_ANALYSIS.md §2.2 참조. 최초 결정 시점엔 8종이었으나 실측이 우선한다).
5. 현행 gonmun 템플릿을 공식 계획안 형식으로 **간주하지 않는다** (폐기).
6. 표지는 고정 레이아웃이다 — 슬로건·CI 위치, 제목 틀(표)·폰트, 하단 연월·기관·부서
   위치가 문서 간 동일하고 색·문구만 변한다 (§3.2.1).
7. **각 본문 페이지에는 슬로건 등 브랜드 요소가 포함되지 않는다** — 본문 상단에
   반복되는 것은 문서 제목(부제 포함) 밴드·쪽번호 같은 문서 정보이지 슬로건이 아니다.
   원 계획서 §11.2의 "본문·참고자료 우측 상단 작은 슬로건" 결정은 이 확인으로
   **폐기**한다.

### 3.1 분석 완료 3종

**A. 세계로배움학교 추진 계획 (HWPX — 유일한 XML 정밀 분석 가능 레퍼런스)**

- 용지 A4, 여백 좌우 20mm·상 15mm·하 15mm → **본문폭 170mm**
- 실사용 charPr 497종 중 상위 패턴:

  - 표: **맑은 고딕 10~11pt + 자간 −10~−16% + 장평 95~100%** ← 줄바꿈 최적화가
    실무에서 자간·장평으로 실제 구현되고 있다는 직접 증거

- 개조식 내어쓰기 실측: `왼쪽여백 830 + 내어쓰기 −2130` (HWPUNIT), 변형 −1488 등
- 표 82개 **전원 repeatHeader=1**. 개체 다수가 treatAsChar=1(소형 표·인라인 박스),
  대형 표만 0 — "표는 무조건 글자처럼 취급 해제"였던 현 구현 가정은 단순화였음
- 폰트 인벤토리: 함초롬바탕·함초롬돋움·맑은 고딕·휴먼명조·HY헤드라인M·한컴산뜻돋움·
  KoPubWorld계열·에스코어드림 등 22종 — 원 계획서 §11.3 글꼴 정책과 일치

**B. 기관배정교사 선발 심사 계획(안) (HWP — 학생교육원 실무형)**

- kordoc 파싱으로 구조 보존 추출 성공(제목 계층·병합 표·이미지) → **HWP 입력 어댑터의
  실현성 실증**
- 패턴: 표(박스형) 표지 제목 + 날짜 + 기관명 / 장 구분 로마숫자(Ⅰ~Ⅴ) + 반복 배경
  그래픽 / 항목기호 ❍ → 1. → 가. → − / `<서식 N>` 마커의 부록(빈 서식 표) 페이지
- 특수문자 실사용: ❍ ￭ ・ ➜ 【】 ❖

**C. 읽걷쓰교육 기본 계획 (PDF 56쪽 — 정책브랜드형)**

- 페이지 유형 시퀀스 실측: p1 표지 → p2 사전검토표 → p3 목차(점선 리더) → p4 요약
  (비전·과제 인포그래픽) → p5~ 본문
- **본문 반복 조판 패턴**: 상단 쪽번호 + **문서 제목(부제 포함) 밴드** 반복
  — 슬로건·CI가 아님(결정 7, 사용자 확인으로 교정). 장 전환 시 로마숫자 장제목 블록,
  항목 계층 ❍/❖/￭/−
- 성과·실적(영역별 표), 추진 경과(연혁 타임라인) 등 본문 하위 변형 존재

#### 3.2.1 표지 고정 레이아웃 명세 (사용자 확인, 2026-07-20)

사용자 확인 사항: 본청 계획안 표지는 문서마다 자유 구성이 아니라 **위치가 거의
고정된 단일 레이아웃**이며, 변하는 것은 색상(제목 틀)과 텍스트 내용뿐이다.

| 슬롯 | 고정 요소 | 변수 |
|---|---|---|
| 상단 | 슬로건 이미지 — 위치 고정 | (기관 프로필에 따른 자산 교체만) |
| 중앙 | 제목 틀 = 표(박스) 형식 + 제목 폰트 고정 | **틀 색상**, 제목 문구 |
| 중앙 보조 | CI — 위치 고정 | (기관 프로필 자산 교체만) |
| 하단 | 연·월 표기 + 기관 문구 + 부서 문구 — 위치 동일 | 연·월 값, 기관·부서명 |

구현 귀결: 표지 생성기는 자유 조합 엔진이 아니라 **고정 앵커 템플릿 + 파라미터
(색·문구·자산) 치환** 방식으로 구현한다. 정확한 앵커 좌표(mm)와 제목 틀의 표 구조
(셀 구성·테두리·채움)는 0단계에서 레퍼런스 표지들을 실측해 확정한다. 이는 현 구현의
표지(문단 나열식 배치)를 폐기하는 추가 근거이기도 하다 — 현 표지는 CI가 위·슬로건이
아래로 순서부터 실제와 다르다.

## 5. 재설계 아키텍처

### 5.1 입력 어댑터 (원 계획 결정 #2·#3 복원)

```
HWP  ─ kordoc 파서 ─┐
HWPX ─ 구조 파서   ─┤→ Plan IR (단일) → 규칙 검사 → 조판 엔진 → HWPX
MD   ─ GFM 파서    ─┤                                └→ 미리보기 (동일 IR·동일 토큰)
TXT  ─ 계층 추정   ─┘
```

- **HWP**: kordoc 파싱 경로 실증됨(§3.1-B). 0단계에서 앱 내 통합 방식 확정
  — 후보 ① kordoc npm 라이브러리 직접 통합(원 계획 결정 #12) ② kordoc CLI 보조
  프로세스. 어느 쪽이든 어댑터 뒤에 격리.
- **HWPX**: 텍스트 추출 폐기. section0.xml을 직접 파싱해 문단·표(병합 포함)·이미지·
  스타일 힌트를 IR로 보존.
- **MD/TXT**: 현 파서를 어댑터 규격으로 재작성. TXT는 공문서 항목기호(□○−❍ 등)
  기반 계층 추정(원 계획 §10.2).

### 5.2 구조 보존형 HWPX 처리

- 입력 HWPX의 표 grid(rowSpan·colSpan)·이미지·문단 계층을 IR에 그대로 싣는다.
- IR 각 블록은 `source`(원문 파일·위치·원문 문자열)를 유지 → 내보내기 전
  "승인되지 않은 내용 변경 0건" 검사(원 계획 §9.1)의 기반.
- 변환 불가 요소(복잡 도형 등)는 몰래 이미지화하지 않고 경고 목록에 올린다.

### 5.3 미리보기 = 출력 동일 모델 (문제: "GUI가 실제 조판 결과를 안 보여줌")

- 단일 원칙: **미리보기와 HWPX 생성기가 같은 IR + 같은 스타일 토큰 JSON을 소비한다.**
- 스타일 토큰을 `tokens.json`(단일 소스)으로 두고 렌더러(React)와 생성기(Python)가
  공유 — 지금처럼 JS 선언(맑은고딕)과 실출력(함초롬바탕)이 어긋나는 구조 원천 차단.
- 조판 결과 검증은 kordoc `render_document`(HWPX→PNG)로 실제 렌더를 미리보기 옆에
  표시하는 방안을 0단계에서 스파이크 — 성공 시 "빠른 미리보기(React) + 실조판
  미리보기(렌더)" 2단으로 확정, 실패 시 COM PDF 렌더로 대체.

### 5.4 페이지 유형 엔진 (사용자 결정 3·4의 구현)

- IR 블록에 페이지 유형 태그를 부여(자동 추정 + 사용자 확정)하고, 유형별 파트
  생성기가 §3.2 매트릭스의 반복 패턴을 적용한다.
- 표지: §3.2.1 고정 앵커 템플릿 — 슬로건·CI·제목 틀·하단 문구의 위치는 고정하고
  색·문구·기관 자산만 치환(결정 1·6).
- 본문 페이지: 브랜드 요소(슬로건·CI) 미포함이 표준(결정 7). 반복 헤더는 문서 제목
  밴드·쪽번호만. 예외적 반복 노출(결정 2)은 프로필 옵션으로 남기되 기본 off이며
  표준 레퍼런스 재현 검증에서는 사용하지 않는다.
- 신규 템플릿: **레퍼런스 A(세계로배움학교 HWPX)의 header.xml에서 실사용 스타일을
  발췌·정리해 "본청 계획안 템플릿"을 구축** — 한컴이 직접 저장한 파일 기반이므로
  dangling ID·열기 거부 리스크가 원천적으로 낮다(이번 세션에서 확인된 함정 회피).

## 9. IR 동등성·구조 일치 판정 기준

### 9.1 4형식 IR 동등성

교차 형식 비교는 원본 고유 정보까지 동일하다고 간주하지 않고 공통 의미 투영
`semanticProjection`을 비교한다.

필수 일치 필드:

- 정규화된 본문 문자열과 블록 순서
- 블록 의미 역할과 제목 단계
- 목록 단계·기호·항목 순서
- 표 행·열 수와 셀 텍스트
- 날짜·시간·금액·수치·고유명사
- 페이지 유형 힌트와 승인 상태

정규화 허용 범위:

- UTF-8 NFC 정규화
- CRLF/LF 차이
- 줄 끝 공백 제거

허용하지 않는 차이:

- 내부 공백, 수치, 날짜, 금액, 고유명사 변경
- 블록 누락·추가·순서 변경
- 승인 상태 변경

비교 제외 필드:

- 원본 파일 경로
- source offset
- 파서별 진단 정보
- 생성 시각
- 형식별 스타일·바이너리 확장 정보

병합 셀·이미지처럼 MD/TXT가 표현할 수 없는 구조는 4형식 공통 fixture에서 제외하고,
HWP↔HWPX 구조 보존 fixture에서 별도로 검사한다.

### 9.2 HWP↔HWPX 구조 보존

다음 항목은 정확히 일치해야 한다.

- 문단·표·이미지 개수
- 표 rowCnt·colCnt·rowSpan·colSpan
- 텍스트·수치·고유명사
- 이미지 SHA-256
- repeatHeader·treatAsChar
- 페이지 유형 시퀀스

허용오차:

- 용지·여백·표 폭: ±0.2mm
- 표지·이미지 앵커 위치와 크기: ±0.5mm
- 글자 크기: ±0.1pt
- 줄간격: ±1%
- 자간·장평: ±1%

페이지 수와 쪽번호 시작값은 정확히 일치해야 한다.

### 9.3 시각·실물 검증

- 한글 COM 열기 및 PDF 변환 성공
- 복구 경고 0건
- 잘림·겹침·빈 페이지·제목 고립 0건
- 승인되지 않은 텍스트 변경 0건
- 본청 및 직속기관 기준 표지의 필수 앵커 누락 0건
- 구조 비교 JSON과 COM 로그를 회귀 corpus에 저장
