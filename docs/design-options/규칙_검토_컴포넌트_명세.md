# ICE Plan Studio 규칙 검토 컴포넌트 명세

- 기준 시안: 03 문서 캔버스형
- 기준 와이어프레임: `규칙_검토_화면_와이어프레임.md`
- 대상 흐름: 표 너비 초과 검토·적용·되돌리기
- 문서 상태: 구현 전 컴포넌트 명세

## 1. 구현 범위

이번 명세는 전체 애플리케이션이 아니라 `규칙 검토` 화면의 첫 동작을 구현하기 위한 것이다.

포함:

- 앱 셸과 단계 레일
- 페이지 썸네일 목록
- A4 문서 캔버스와 선택 객체 오버레이
- 규칙 인스펙터
- 현재값·권장값 비교
- 적용 방법 선택
- 적용·되돌리기·다음 항목
- 빠른 미리보기와 상태 표시

제외:

- 실제 HWPX XML 변환 알고리즘
- 한글 COM 자동화 구현
- 표 병합·분할 편집
- 자유 배치 캔버스
- 전체 스타일 편집기

## 3. 컴포넌트별 책임과 상태

### 3.1 AppTopBar

| 항목 | 명세 |
|---|---|
| 책임 | 프로젝트명, 저장 상태, 한글 작업본 동기화 상태, 도움말·설정 표시 |
| 기본 높이 | 56px |
| 상태 | 저장됨, 저장 중, 저장 필요, 동기화 대기, 동기화 경고 |
| 상호작용 | 프로젝트 메뉴, 저장, 설정, 도움말 |
| 금지 | 문서 규칙 경고를 상단에 중복 표시, 장식용 진행 애니메이션 |

`SaveState`와 `HancomSyncState`는 색상만으로 상태를 전달하지 않는다. 상태 텍스트와 아이콘 이름을 함께 제공한다.

### 3.2 WorkflowRail / WorkflowStep

| 항목 | 명세 |
|---|---|
| 책임 | 전체 작업 흐름과 현재 위치 표시 |
| 단계 | 시작, 분석, 메타데이터, 구조 편집, 규칙 검토, 내보내기 |
| 상태 | 잠금, 대기, 진행 중, 완료, 검토 필요 |
| 선택 | 현재 단계와 완료 단계만 직접 이동 가능. 이전 단계 이동 시 변경사항 확인 |
| 축약 | 1280px에서 번호·아이콘 중심으로 축약, 포커스 시 라벨 표시 |

현재 단계는 좌측 강조선·배경·텍스트 굵기를 함께 사용한다. 완료는 체크 아이콘과 `완료` 텍스트를 함께 사용한다.

### 3.3 PageThumbnailRail / PageThumbnail

| 항목 | 명세 |
|---|---|
| 책임 | 문서 페이지 탐색과 페이지별 문제 수 표시 |
| 기본 폭 | 120px, 축약 시 96px |
| 상태 | 기본, 현재 페이지, 오류 있음, 경고 있음, 처리 중 |
| 상호작용 | 클릭으로 페이지 이동, Enter로 선택, 방향키로 이동 |
| 접근성 | `페이지 3, 오류 1, 경고 0` 형식의 accessible name |

썸네일 클릭은 탐색만 수행한다. 자동 수정은 인스펙터의 명시적 적용에서만 수행한다.

### 3.4 DocumentViewport / PreviewToolbar

`DocumentViewport`는 문서와 앱 UI를 분리하는 중립색 작업공간이다.

| 도구 | 역할 | 키보드 |
|---|---|---|
| 선택 | 문서 객체 선택 | `V` |
| 이동 | 캔버스 이동 | `Space` 누른 채 드래그 |
| 확대 | 25~200% 확대 | `Ctrl++` |
| 축소 | 25~200% 축소 | `Ctrl+-` |
| 페이지 맞춤 | 현재 페이지를 작업영역에 맞춤 | `Ctrl+0` |
| 보기 | 한 페이지·두 페이지 전환 | `1`, `2` |

툴바의 아이콘 버튼에는 tooltip과 accessible name이 있어야 하며, 선택 도구가 기본값이다.

### 3.5 A4Page / DocumentObjectOverlay

| 항목 | 명세 |
|---|---|
| 책임 | 실제 HWPX 페이지의 렌더링 결과와 객체 위치 표시 |
| 용지 | A4 210×297mm 기준, 실제 비율 유지 |
| 선택 | 선택 객체에 1px 점선 외곽선과 번호 표시 |
| 경고 | 문제 객체의 실제 경계에 연결된 선·번호·경고 아이콘 |
| 보호 | 문서 본문은 검토 화면에서 직접 임의 편집하지 않음 |

오버레이 좌표는 IR의 객체 ID와 페이지 좌표를 참조한다. 픽셀 위치만 저장하지 않는다.

### 3.6 RuleInspector

인스펙터는 `IssueHeader → IssueTargetCard → MeasurementComparison → ResolutionChoice → BeforeAfterPreview → RuleEvidence → InspectorActionBar` 순서로 고정한다.

#### IssueHeader

- 문제 번호, 규칙 종류, 심각도, 현재 항목 위치 표시
- 예: `① 표 너비 초과 · 오류`
- 제목만으로 문제가 이해되도록 한다.

#### IssueTargetCard

- 객체 종류: 표
- 객체 이름: 추진과제 표
- 페이지: 1
- 객체 ID: `TBL_01`
- 캔버스 선택과 동일한 객체 ID를 사용한다.

#### MeasurementComparison

| 필드 | 값 | 표현 |
|---|---:|---|
| 현재 너비 | 164mm | 현재값 |
| 권장 최대 너비 | 160mm | 규칙값 |
| 초과 | 4mm | 오류 차이 |

수치에는 반드시 단위를 표시한다. 단위 없는 숫자는 허용하지 않는다.

#### ResolutionChoice

- `권장 최대 너비로 조정`: 기본 선택
- `내용을 조정하여 너비 유지`: 대안 선택
- 라디오 선택 변경만으로 문서를 수정하지 않는다.

#### BeforeAfterPreview

- 적용 전 표와 적용 후 표를 좌우 비교
- 행·열 수와 본문 내용은 유지
- 변경 범위가 열 너비인지, 줄바꿈인지, 페이지 나눔인지 표시
- 실제 재조판 결과가 준비되지 않았으면 `예상 미리보기`로 표시

#### RuleEvidence

- 규칙 ID
- 규칙 설명
- 적용 우선순위
- 출처 또는 프로필 이름
- 펼치기 전에는 한 줄 요약만 표시

#### InspectorActionBar

- 기본 버튼: `적용`
- 보조 버튼: `되돌리기`
- 보조 텍스트 버튼: `다음 항목`
- 적용 중에는 적용 버튼을 비활성화하고 진행 상태를 표시

## 4. 데이터 계약

문서 UI는 HWPX XML을 직접 읽지 않고 Canonical Plan IR의 검토 모델을 받는다.

```ts
type ReviewIssue = {
  id: string;
  kind: "table-width" | "margin" | "page-break" | "font" | "overflow";
  severity: "error" | "warning" | "info";
  pageIndex: number;
  objectId: string;
  objectLabel: string;
  title: string;
  message: string;
  current: Measurement;
  recommended: Measurement;
  delta: Measurement;
  sourceRuleId: string;
  sourceProfile: string;
  options: ResolutionOption[];
  selectedOptionId: string;
  status: "open" | "applying" | "applied" | "failed" | "reverted";
};

type Measurement = {
  value: number;
  unit: "mm" | "pt" | "px" | "percent";
};

type ResolutionOption = {
  id: string;
  label: string;
  description: string;
  preview: "width-only" | "reflow" | "page-break" | "manual-review";
  requiresConfirmation: boolean;
};
```

UI 컴포넌트는 `ReviewIssue`를 변경하지 않고, 이벤트를 통해 적용을 요청한다.

## 5. 이벤트 계약

| 이벤트 | 발생 | 처리 |
|---|---|---|
| `reviewIssueSelected` | 썸네일·오버레이·항목 카드 선택 | 해당 페이지와 객체를 함께 포커스 |
| `resolutionOptionChanged` | 라디오 변경 | 예상 미리보기만 갱신 |
| `reviewIssueApplyRequested` | 적용 클릭 또는 Enter | IR 조정 요청과 스냅샷 생성 |
| `reviewIssueApplied` | 재조판 성공 | 캔버스·수치·목차·페이지 상태 갱신 |
| `reviewIssueApplyFailed` | 재조판 실패 | 원인·복구 방법 표시, 원본 보존 |
| `reviewIssueReverted` | 되돌리기 또는 Ctrl+Z | 직전 스냅샷 복원 |
| `reviewIssueNextRequested` | 다음 항목 또는 PageDown | 다음 이슈로 이동 |
| `hancomValidationChanged` | 한글 검증 상태 변경 | 최종 검증 배지 갱신 |

색상은 `brand.*`, `surface.*`, `text.*`, `border.*`, `status.*`, `document.*` 의미 토큰만 사용한다. 공식 CI에서 추출한 값과 검토 상태 색상을 동일 토큰으로 쓰지 않는다.

## 7. 접근성 계약

- 모든 인터랙티브 컴포넌트는 키보드 포커스와 accessible name을 가진다.
- `aria-current`는 현재 단계와 현재 페이지에 사용한다.
- 인스펙터 선택 변경은 `aria-live="polite"` 영역에 요약한다.
- 오류는 `role="alert"`로 전달하되, 적용 중 상태는 별도 `status`로 전달한다.
- 표 너비 문제는 `표 너비 초과, 페이지 1, 현재 164밀리미터, 권장 160밀리미터`로 읽힌다.
- 색상만으로 오류·경고·완료를 구분하지 않는다.
- 포커스 링은 2px 이상이며 문서 객체 점선과 구별되는 토큰을 사용한다.
- 200% 배율에서 인스펙터의 기본 행동과 문제 요약이 먼저 보인다.

## 8. 상태별 승인 기준

### 기본 상태

- 첫 번째 검토 항목이 선택되어 있다.
- 페이지 썸네일·캔버스 객체·인스펙터의 페이지와 객체 ID가 일치한다.
- 적용 버튼은 활성 상태이고 기본 라디오가 선택되어 있다.

### 적용 중

- 적용 버튼은 중복 실행되지 않는다.
- `조판 중`과 현재 대상 객체를 표시한다.
- 취소가 지원되지 않는 단계라면 그 사실을 표시하고 창을 닫지 못하게 한다.

### 적용 완료

- 캔버스 표 너비가 160mm로 갱신된다.
- 문제 항목은 완료 또는 다음 검토 필요 상태로 바뀐다.
- 자동 저장 스냅샷이 생성된다.
- 한글 최종 검증 전에는 `빠른 미리보기 완료`로만 표시한다.

### 적용 실패

- 원본 문서와 직전 스냅샷을 유지한다.
- 실패 원인과 재시도·수동 검토 경로를 표시한다.
- 오류가 사라진 것처럼 표시하지 않는다.

## 9. 컴포넌트 구현 순서

1. `AppShell + WorkflowRail + AppStatusBar`
2. `PageThumbnailRail + PreviewToolbar`
3. `A4Page + DocumentObjectOverlay`
4. `RuleInspector + MeasurementComparison`
5. `ResolutionChoice + BeforeAfterPreview`
6. `InspectorActionBar + 상태 전환`
7. 키보드·스크린리더·배율 검증

각 단계는 실제 HWPX 변환 엔진이 완성되기 전에도 고정 fixture로 렌더링 가능해야 한다.

## 10. 컴포넌트 완료 게이트

- [ ] 모든 컴포넌트가 단일 책임을 가진다.
- [ ] 객체 식별자는 픽셀이 아니라 IR의 페이지·객체 ID에 연결된다.
- [ ] 현재값·권장값·단위·근거가 함께 표시된다.
- [ ] 적용 전 미리보기와 적용 후 결과가 분리된다.
- [ ] 실패 시 원본과 스냅샷이 보존된다.
- [ ] 1440px·1280px·Windows 200%에서 주요 행동이 유지된다.
- [ ] 키보드만으로 선택·적용·되돌리기·다음 항목 이동이 가능하다.
- [ ] 상태와 오류가 색상 외 텍스트·아이콘으로도 전달된다.
- [ ] 컴포넌트 구현 전에 실제 CI·문서 글꼴 토큰을 확정한다.
