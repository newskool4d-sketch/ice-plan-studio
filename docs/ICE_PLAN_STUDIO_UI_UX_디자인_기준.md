# ICE Plan Studio UI·UX 디자인 기준

- 문서 상태: MVP 디자인 레퍼런스 기준선
- 작성일: 2026-07-19
- 적용 대상: Windows용 교육청 계획안 자동서식 GUI
- 관련 문서: `교육청_계획안_자동서식_GUI_MVP_구현계획.md`

## 1. 결론

ICE Plan Studio는 마케팅 사이트처럼 화려한 화면이 아니라, **공공업무 도구의 신뢰성·정밀성·검증 가능성**을 우선하는 데스크톱 워크벤치로 설계한다.

시각적 뼈대는 **Swiss / International Style의 정렬과 정보 위계**에 두고, 실제 컴포넌트와 접근성은 **IBM Carbon 계열의 엔터프라이즈 규율**을 참고한다. 문서 분석·편집 작업공간에는 Cursor와 Miro의 생산성 도구 패턴을 제한적으로 적용하며, Airbnb 패턴은 단계형 입력과 명확한 다음 행동에만 참고한다.

Design -isms의 화면 자체를 복제하지 않는다. 해당 사이트는 디자인 분류와 구현 원칙을 찾는 **참고 사전**으로 사용한다.

## 3. 제품 성격

디자인 판단은 다음 다섯 단어로 검증한다.

1. **정확함**: 사용자가 무엇이 변환되고 무엇이 보존되는지 알 수 있어야 한다.
2. **차분함**: 긴 문서 작업 중 시각적 피로를 만들지 않아야 한다.
3. **검증 가능함**: 경고와 수정 근거가 문서 위치와 연결되어야 한다.
4. **익숙함**: Windows와 한글 문서를 사용하는 행정 실무자가 새 조작법을 많이 배우지 않아야 한다.
5. **공적임**: 장식보다 문서·규칙·상태가 먼저 보여야 한다.

## 4. 애플리케이션 셸

### 4.1 기본 배치

데스크톱 기본 화면은 다음 네 영역으로 구성한다.

| 영역 | 권장 크기 | 역할 |
|---|---:|---|
| 상단 앱 바 | 56px | 프로젝트명, 저장 상태, 한글 동기화 상태, 도움말, 전역 작업 |
| 좌측 단계 레일 | 224~240px | 시작→분석→메타데이터→구조 편집→규칙 검토→내보내기 |
| 중앙 작업영역 | 가변 | 입력 폼, 구조 편집기, A4 미리보기 |
| 우측 인스펙터 | 304~336px | 선택 블록 속성, 규칙 근거, 수정 전후, 경고 설명 |

문서 미리보기 화면에서는 중앙을 `페이지 썸네일 / A4 캔버스 / 규칙 인스펙터`의 3열 구조로 바꾼다. 패널 너비는 드래그로 조절할 수 있지만, 초기 MVP에서는 사용자가 레이아웃을 완전히 해체하지 못하도록 제한한다.

### 4.2 화면 폭과 Windows 배율

- 넓은 화면: 좌측 단계 레일과 우측 인스펙터를 모두 표시한다.
- 중간 화면: 좌측은 아이콘+축약 라벨로 줄이고 우측 인스펙터 너비를 축소한다.
- 좁은 논리 해상도 또는 175~200% 배율: 좌우 패널을 서랍 방식으로 전환하고 중앙 작업을 보존한다.
- 최소 창 크기에서 기본·취소·저장·내보내기 버튼이 잘리면 안 된다.
- 모바일 반응형은 대상이 아니지만, Windows 디스플레이 배율에 따른 재배치는 필수다.

## 5. 디자인 토큰 방향

### 5.1 색상

색상값은 소스코드에 직접 흩뿌리지 않고 의미 토큰으로 관리한다.

| 토큰군 | 용도 |
|---|---|
| `brand.*` | 승인된 인천광역시교육청 CI 원본에서 추출한 공식 강조색 |
| `surface.*` | 앱 배경, 패널, 카드, A4 캔버스 배경 |
| `text.*` | 기본, 보조, 비활성, 역상 텍스트 |
| `border.*` | 패널 구분, 입력 테두리, 표 경계 |
| `status.*` | 성공, 안내, 경고, 오류, 처리 중 |
| `document.*` | A4 용지, 페이지 그림자, 선택 블록, 조판 경계 |

원칙:

- 화면당 브랜드 강조색은 원칙적으로 한 계열만 사용한다.
- CI의 여러 색상을 버튼·카드마다 나눠 쓰지 않는다.
- 상태 색상은 브랜드색과 분리하고 텍스트·아이콘·형태를 함께 제공한다.
- A4 문서 자체 색상과 앱 UI 색상이 경쟁하지 않도록 작업영역은 중립색으로 유지한다.
- 공식 CI 색상은 원본 마스터 파일 확인 후 확정하며, 현재 PNG에서 임의 추출한 값을 최종값으로 고정하지 않는다.

### 5.2 타이포그래피

앱 UI와 생성 문서의 글꼴 체계를 분리한다.

| 영역 | 원칙 |
|---|---|
| 앱 UI | 한국어 가독성이 좋은 산세리프 한 계열. `Pretendard Variable` 사용은 라이선스·패키징 검토 후 결정하고, 기본 대체는 `맑은 고딕`, `Noto Sans KR`, system-ui 순으로 둔다. |
| 기술값 | 페이지 번호, 치수, XML 경로, 진단 코드는 고정폭 글꼴을 제한적으로 사용한다. |
| 문서 캔버스 | 실제 HWPX의 제목·본문·표 글꼴을 그대로 표시한다. 앱 UI 글꼴로 대체하지 않는다. |

권장 UI 위계:

| 용도 | 크기·굵기 방향 |
|---|---|
| 화면 제목 | 24~28px / 600 |
| 섹션 제목 | 18~20px / 600 |
| 카드·패널 제목 | 15~16px / 600 |
| 기본 본문·입력 | 14~16px / 400 |
| 보조 설명 | 12~13px / 400 |
| 버튼·탭 | 14px / 500~600 |

색상을 제거해도 크기·굵기·간격만으로 읽기 순서가 드러나야 한다.

### 5.3 간격과 형태

- 기본 단위: 4px
- 자주 쓰는 간격: 4, 8, 12, 16, 24, 32, 48px
- 패널 내부 기본 여백: 16 또는 24px
- 조밀한 표·목록 행: 36~40px, 주요 입력·버튼: 40~44px
- 모서리: 0, 4, 8px의 세 단계만 기본 사용
- pill 형태는 상태 배지·필터·짧은 토글에만 사용
- 그림자는 대화상자·팝오버·A4 용지 분리에만 제한하고, 일반 카드에는 경계선과 표면 차이를 사용

## 6. 핵심 컴포넌트 규칙

### 6.1 버튼

- 화면당 기본 버튼은 하나만 강하게 표시한다.
- 기본·보조·텍스트·위험 버튼의 네 위계를 유지한다.
- 버튼 높이는 기본 40px, 중요한 내보내기·확인 작업은 44px 이상으로 한다.
- 아이콘만 있는 버튼은 툴팁과 접근성 이름을 모두 제공한다.
- 비활성 버튼은 이유를 인접 설명이나 툴팁으로 알려준다.

### 6.2 입력과 메타데이터 확인

- 라벨은 입력칸 안의 placeholder로 대체하지 않는다.
- 자동 추출값에는 `자동 추출`, 사용자가 수정한 값에는 `수정됨` 상태를 표시한다.
- 필수 확인 항목은 색상만이 아니라 아이콘·텍스트·그룹 제목으로 구분한다.
- 오류는 필드 바로 아래에 원인과 해결 방법을 함께 표시한다.

### 6.3 표와 목록

- 헤더는 스크롤 시 고정한다.
- 선택 행, 편집 행, 경고 행의 상태를 서로 다르게 표현한다.
- 긴 파일명·문서 제목은 말줄임만 하지 말고 전체값을 확인할 수 있게 한다.
- 열 너비 자동조정 결과와 사용자가 고정한 너비를 구분한다.
- 수치·단위·상태 열은 정렬 기준을 일관되게 유지한다.

### 6.4 상태와 진행

작업 상태는 최소 다음 단계로 통일한다.

`대기 → 분석 중 → 검토 필요 → 수정됨 → 빠른 미리보기 완료 → 한글 검증 완료 → 내보내기 완료`

- 상태는 색상, 아이콘, 텍스트를 함께 사용한다.
- 장시간 작업에는 진행률, 현재 단계, 취소 버튼을 제공한다.
- 완료 표시와 한글 최종검증 완료 표시는 구분한다.
- Cursor식 다색 타임라인은 그대로 사용하지 않고, 단계의 의미를 보여주는 제한된 상태 체계로 변환한다.

### 6.5 문서 캔버스와 인스펙터

- A4 페이지는 중립 회색 작업영역 위에 흰 용지로 표시한다.
- 선택된 문단·표·이미지는 얇은 외곽선으로 표시하고 문서 내용 자체를 가리지 않는다.
- Technical Blueprint 방식은 오류 설명에만 사용한다. 예: `표 너비 164mm`, `오른쪽 여백 초과 3mm`, `다음 페이지로 행 이동`.
- 모든 주석선은 실제 대상과 연결되어야 하며 장식용 번호·치수선은 금지한다.
- 오른쪽 인스펙터에는 `현재값 / 규칙값 / 변경 제안 / 적용 여부`를 같은 순서로 보여준다.

## 7. 여섯 화면별 디자인 방향

| 화면 | 핵심 경험 | 참고 패턴 |
|---|---|---|
| 시작 | 새 문서, 기존 프로젝트, 최근 작업을 빠르게 선택 | Airbnb의 명확한 진입 행동 + IBM의 단순한 타일 |
| 분석 | 진행 단계와 발견 항목을 신뢰감 있게 확인 | Cursor의 작업 단계 표시를 단색·의미 중심으로 단순화 |
| 메타데이터 | 자동 추출값을 확인하고 누락값만 수정 | IBM Carbon 폼, 라벨·오류·포커스 규칙 |
| 구조 편집 | 문서 계층과 순서를 제한된 방식으로 편집 | Miro의 작업영역+인스펙터, 자유 캔버스는 제외 |
| 규칙 검토 | 수정 전후와 근거를 항목별로 승인 | Swiss 정보 위계 + Technical Blueprint 설명 오버레이 |
| 내보내기 | 빠른 미리보기와 한글 검증 상태를 구분하고 저장 | Material의 명확한 상태 전환 + 단일 기본 행동 |

프로필 관리자는 별도 화면으로 두되, Design -isms의 3문항 스타일 탐색기처럼 짧은 질문으로 `기관 유형 / 브랜드 자산 / 템플릿 계열`을 선택하는 보조 흐름을 후속 검토할 수 있다.

## 8. 접근성 기준

- 모든 주요 흐름을 키보드만으로 완료할 수 있어야 한다.
- 포커스는 최소 2px 외곽선과 충분한 대비로 표시한다.
- 포커스 순서는 시각적 읽기 순서와 일치해야 한다.
- 클릭 목표는 가급적 44×44px 이상을 확보한다.
- 본문과 컨트롤 텍스트는 WCAG AA 대비를 목표로 한다.
- 경고·오류·완료를 색상만으로 전달하지 않는다.
- 스크린리더용 이름, 상태, 설명 관계를 제공한다.
- Windows 100~200% 배율에서 중요한 정보와 기본 행동이 잘리지 않아야 한다.
- 움직임 감소 설정을 존중하고, 상태 전달에 필요하지 않은 애니메이션은 제거한다.

## 9. 모션 원칙

- 기본 전환: 120~200ms
- 패널 열기·선택 상태·진행 상태 설명에만 사용
- 화면 진입용 과장된 fade, scale, parallax는 사용하지 않는다.
- 문서 재조판 시 페이지가 갑자기 튀지 않도록 변경된 위치를 짧게 강조한다.
- 처리 중 애니메이션은 실제 진행 상태와 연결하고 무한 장식 애니메이션을 사용하지 않는다.

## 10. 금지 목록

- 보라·청록 그라데이션을 기본 SaaS 분위기로 사용하는 것
- 반투명 유리 카드와 blur를 업무 화면 전반에 사용하는 것
- 의미 없는 3D 아이콘·스파클·로봇 이미지를 배치하는 것
- 화면마다 다른 radius·그림자·버튼 체계를 사용하는 것
- 모든 정보를 카드로 감싸 위계를 약화하는 것
- CI의 여러 색상을 장식용으로 분산 사용하는 것
- 문서 경고를 색상이나 작은 배지만으로 표시하는 것
- 문서 미리보기보다 앱 장식을 더 눈에 띄게 만드는 것
- 한글 글꼴이 없는 영문 브랜드 서체를 UI 기본 글꼴로 강제하는 것

## 11. 구현 전 디자인 게이트

실제 Electron UI를 만들기 전에 다음 세 가지 시안을 같은 콘텐츠와 같은 화면 크기로 비교한다.

1. **정밀형**: Swiss + IBM 중심
2. **워크벤치형**: IBM + Cursor 중심
3. **문서 캔버스형**: IBM + Miro 중심

각 시안은 최소 `규칙 검토 화면`과 `문서 미리보기 화면`을 포함해야 한다. 선택 전에는 전체 애플리케이션을 구현하지 않는다.

선택 기준:

- 10초 안에 현재 단계와 다음 행동을 알 수 있는가
- 문서와 앱 UI가 시각적으로 경쟁하지 않는가
- 경고의 위치·원인·해결 방법이 연결되어 보이는가
- 150페이지 문서와 수백 개 표가 있어도 화면 구조가 유지되는가
- Windows 200% 배율에서도 작업을 완료할 수 있는가
- 장식을 제거해도 정보 위계가 분명한가

## 12. 현재 결정과 남은 결정

### 확정

- Swiss + IBM을 기본 축으로 사용
- Cursor·Miro·Airbnb는 기능별 참고로만 제한
- 앱 UI와 HWPX 문서 서체 체계를 분리
- 단일 강조색, 4px 그리드, 얇은 경계선, 제한된 그림자
- 문서 캔버스와 검증 근거를 화면의 중심으로 배치
- AI Slop 진단 항목을 디자인 검수 체크리스트에 포함

### 시안 단계에서 확정

- 공식 CI 기반 앱 강조색의 정확한 값
- 좌측 단계 레일의 전체 라벨형과 축약형 전환 기준
- 기본 모서리 4px 또는 8px 비중
- 문서 캔버스 배경의 명도
- 규칙 검토 화면의 `목록 우선`과 `문서 위치 우선` 배치
- UI 글꼴의 패키징 여부와 최종 대체 순서

## 13. 출처 사용 원칙

- 참고 사이트와 브랜드 분석의 구조·원칙만 차용한다.
- 타사 로고, 브랜드 색상, 독점 글꼴, 일러스트, 화면을 제품 자산으로 복사하지 않는다.
- 인천광역시교육청 CI·슬로건은 제공된 공식 원본만 사용한다.
- 외부 디자인 레퍼런스의 스크린샷이나 생성 이미지는 제품에 포함하지 않는다.
- 실제 구현은 ICE Plan Studio 고유 토큰과 컴포넌트로 다시 정의한다.
