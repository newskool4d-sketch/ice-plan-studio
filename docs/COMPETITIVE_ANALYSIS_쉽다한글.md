# 참고 제품 분석: 쉽다한글 1.4.0

| 항목 | 내용 |
|---|---|
| 분석일 | 2026. 7. 20. |
| 분석 방법 | 설치본 정적 분석 (실행 파일 문자열 스캔 + 동봉 HWPX 조각 XML 검사, 읽기 전용) |
| 제작자 | 브로준(조준형), ⓒ 2026 — 개인 개발자, 커뮤니티 배포물(공개 웹 검색 결과 없음) |
| 설치 규모 | Inno Setup 6.7 설치기 30.7MB → 설치 후 124파일 129.6MB |
| 저작권 주의 | **코드·상용구 파일은 타인의 저작물 — 복제·동봉 금지.** 이 문서는 구조 관찰로 얻은 접근 방식만 기록한다 |

## 1. 제품 정체

교사용 **한글 문서 꾸미기 도우미**. 사용자가 한글에서 문서를 작성하는 중에
WebView UI에서 상용구(제목 박스·중제목·표 스타일)를 골라 현재 커서 위치에
삽입한다. 동봉 샘플이 가정통신문·보고서인 것으로 보아 대상은 학교 현장 교사다.

ICE Plan Studio와 겹치지 않는다 — 쉽다한글은 "한글 안에서 꾸미기 조수",
우리는 "MD/HWP 내용 → 완성된 본청 계획안 자동 생성"이다.

## 2. 기술 스택 (실측)

| 구성 | 쉽다한글 | ICE Plan Studio |
|---|---|---|
| 코어 | Python 3.12, PyInstaller 단일 exe(61.6MB) | Python 스크립트 (Electron이 스폰) |
| 한글 연동 | pywin32 COM — `HWPFrame` + `RegisterModule` 확인 | 동일 |
| GUI | pywebview + WebView2 (HTML/JS) | Electron + React |
| 이미지 처리 | PIL + numpy | stdlib PNG/JPEG 파서 (의존성 제거함) |
| 서식 자산 | HWPX 조각 15개 (외부 폴더, 사용자 확장 가능) | boncheong 템플릿 + cover-anchor.xml |

exe 문자열 스캔에서 확인된 한글 COM API 사용 흔적:
`InsertFile`(×4) `CharShape`(×28) `GetTextFile`/`SetTextFile` `MoveDocEnd`
`BreakPara` `SaveAs` `FileOpen` `HAction`/`HParameterSet`/`CreateAction`

## 3. 핵심 메커니즘: HWPX 조각 + `InsertFile`

상용구를 **각각 독립된 완전한 HWPX 파일**로 만들어 두고, 한글 COM의
`InsertFile`로 라이브 문서의 커서 위치에 삽입한다. XML을 직접 조작하지 않고
스타일 병합을 한글 엔진에 맡기는 방식. 삽입 후 `CharShape`로 글자 서식을
미세 조정한다.

동봉 상용구 구성 (`%LOCALAPPDATA%\Programs\쉽다한글\상용구\`):

| 조각 | 구조 (XML 실측) |
|---|---|
| 상용구(제목·검정/빨강/초록/태극/파랑) 5종 | **동일한 3행×1열 표(149×22mm), 색 장식만 다름** |
| 상용구(로마자 대제목) | 1행×3열 표(149×10mm), #003366 채움 + "Ⅰ" |
| 본문_본문/중제목/참고 | 문단 스타일 조각 (□ 중제목 등) |
| 표(보기)/표(인용구) | 3×5 표 스타일, `<표제목>` 컨벤션 |
| 샘플서식 | 가정통신문·보고서 완성 서식 2종 |

사용 폰트: 함초롬돋움·함초롬바탕·HY헤드라인M·휴먼명조.

## 4. 우리 설계와의 교차 검증 (이 분석의 최대 가치)

1. **"제목 틀 = 표, 색만 변수" 실증** — 5색 제목 상용구가 전부 동일 표 구조에
   장식만 다름. 우리가 레퍼런스 실측으로 확정한 표지 앵커 개념(REBASELINE_PLAN
   §3.2.1)과 동일한 접근을 상용 제품이 이미 쓰고 있다.
2. **박스형 장제목 계열 실증** — 로마자 대제목 박스가 레퍼런스 A의 장제목 박스
   패턴(BASELINE_ANALYSIS §2.3)과 동일.
3. **폰트 셋 일치** — BASELINE_ANALYSIS §4의 공문서 폰트 셋과 동일.
4. **아키텍처 생존 증명** — Python + 한글 COM + 웹 GUI 조합이 실제 배포되어
   쓰이는 검증된 방식임을 보여준다.

## 5. 채택 후보 (구현 아이디어 차원)

| 아이디어 | 적용처 |
|---|---|
| `InsertFile` 기반 라이브 삽입 | 원 계획서 §6 "한글 연동 편집"의 가벼운 구현 경로. 작업 사본 왕복·동기화보다 단순. 2단계 이후 설계 시 검토 |
| 상용구 = 독립 HWPX 조각 라이브러리 | 페이지 유형 파트 생성기를 "XML 문자열 조립"보다 "검증된 HWPX 조각 + 치환"으로 구성하는 방향의 근거 보강 (cover-anchor.xml이 이미 이 방향) |
| 상용구 폴더 사용자 확장(`__sync_test__.txt` 관찰) | 프로필·상용구 커스터마이징 UX 아이디어 |
| pywebview 패키징 (설치기 30MB) | Electron 대비 경량 배포 대안으로 장기 참고만 |

## 6. 차이점 유지 (우리 제품 방향에 영향 없음)

- 쉽다한글의 조각 폭은 149mm(느슨한 범용 폭) — 우리는 본청 계획안 실측 170mm.
- 쉽다한글은 문서 유형·페이지 시퀀스·규칙 검사가 없다 — 우리의 핵심 차별점
  (페이지 유형 9종, 공문서 규칙 엔진, IR 동등성 게이트)은 그대로 유효하다.
